# JUDGE — платформа автоматической оценки хакатонов

JUDGE автоматизирует проверку и оценку решений команд на хакатоне: код, документация,
презентация, скринкаст и алгоритмические задачи проверяются автоматически, а жюри
выставляет экспертные оценки по настраиваемым критериям. Итоговый рейтинг строится
из суммы автоматических и экспертных баллов.

---

## Быстрый старт (Docker)

Нужен только установленный Docker. Одна команда поднимает весь стенд:

```bash
docker compose up --build
```

После запуска:

| Что | Адрес |
|-----|-------|
| Веб-интерфейс | http://localhost:3000 |
| Backend API | http://localhost:8000 |
| Документация API (Swagger) | http://localhost:8000/docs |

Демо-данные (команды, кейсы, критерии, алгоритмические задачи) загружаются
автоматически при первом старте.

## Возможности

### Для участников
- Создание команды и вступление по коду приглашения
- Загрузка кода: **ссылка на GitHub** или **ZIP-архив**
- Загрузка документации (PDF / DOCX / Markdown) и презентации (PPTX / PDF)
- Скринкаст: **загрузка файла** или **ссылка** на YouTube / Vimeo
- Решение **алгоритмических задач** онлайн на Python, C++ или Java

### Автоматические проверки
- **Код** — структура репозитория (README, лицензия, файл зависимостей, скрипты
  запуска, `.gitignore`), число коммитов, **подсчёт строк кода, линтер flake8,
  сложность (radon), поиск захардкоженных секретов**, а также опциональный
  **запуск тестов команды** (pytest) в песочнице
- **Документация** — наличие обязательных разделов (**настраиваются организатором**),
  объём текста, **изображения и схемы**
- **Презентация** — количество слайдов и ключевые темы (проблема, решение,
  аудитория, стек, демо, команда, контакты) — **список настраивается организатором**
- **Скринкаст** — длительность (3–5 мин), разрешение, кодек, наличие аудио;
  опциональная **транскрипция и краткое содержание** (Whisper)

### Алгоритмический модуль
Организатор создаёт задачи с тестами и лимитами по времени/памяти. Участники
отправляют решения, которые запускаются в изолированной песочнице. Вердикты:
**OK / WA / TL / ML / RE / CE**, с детализацией по каждому тесту и историей попыток.

### Оценивание и рейтинг
- Организатор задаёт **критерии оценки и их веса**
- Жюри оценивает каждый критерий — итоговый балл считается как взвешенное среднее
- **Карточка команды** для жюри: все артефакты, результаты автопроверок,
  транскрипция, скачивание файлов и панель оценки в одном месте
- **Рейтинг** с подиумом топ-3, фильтром по кейсу и разбивкой балла (авто + жюри)

### Для организатора
- Управление **кейсами (треками)**, **критериями оценки** и **обязательными
  разделами** документации и презентации
- **Аналитика**: распределение баллов, доля пройденных проверок, средние по кейсам
- **Экспорт результатов в CSV**
- Лента уведомлений о событиях в реальном времени

## Локальный запуск (без Docker)

### Backend

```bash
cd backend
pip install -r requirements.txt
python seed.py                              # загрузка демо-данных (SQLite)
uvicorn app.main:app --reload --port 8000
```

### Frontend

```bash
cd frontend
npm install
npm run dev                                 # проксирует /api на http://localhost:8000
```

Откройте http://localhost:5173

> В локальном режиме по умолчанию используется SQLite и встроенная обработка задач
> (без Celery/Redis) — никаких дополнительных сервисов поднимать не нужно.

---

## Настройка (переменные окружения)

См. `backend/app/config.py`.

| Переменная | По умолчанию | Назначение |
|------------|--------------|------------|
| `DATABASE_URL` | `sqlite:///./judge.db` | SQLite (dev) или PostgreSQL (prod) |
| `SECRET_KEY` | dev-ключ | Ключ подписи JWT-токенов |
| `USE_CELERY` | `false` | `true` — проверки через очередь Celery/Redis, иначе в процессе |
| `CELERY_BROKER_URL` | `redis://localhost:6379/0` | Брокер Redis |
| `RUN_TEAM_TESTS` | `false` | `true` — запускать тесты команды при проверке кода |

## Тесты и качество кода

```bash
cd backend && pytest          # 23 теста (auth, все автопроверки, смоук API по ролям)
cd backend && flake8 app seed.py tests   # статический анализ, 0 замечаний
cd frontend && npx tsc --noEmit          # типобезопасность фронтенда, 0 ошибок
```

Тесты используют изолированную SQLite-БД во временной папке и не трогают рабочие
данные. Подробнее — [docs/TESTING.md](docs/TESTING.md). Справочник эндпоинтов —
[docs/API.md](docs/API.md).

### Автоматическая транскрипция скринкаста (опционально)

Метаданные видео (длительность, разрешение, кодек, наличие аудио) проверяются
всегда через `ffprobe`. Транскрипция и краткое содержание включаются установкой
`openai-whisper` (тяжёлая зависимость ~1.5 ГБ с torch — раскомментируйте строку в
`backend/requirements.txt`). Само **краткое содержание формируется экстрактивным
алгоритмом без ML-зависимостей** ([`summarize`](backend/app/checks/video_checker.py)),
поэтому работает на любом транскрипте.

## Архитектура

- **Backend**: FastAPI + SQLAlchemy, SQLite (dev) / PostgreSQL (prod)
- **Frontend**: React 18 + Vite + Tailwind CSS v4 + Radix UI
- **Очередь задач**: Celery + Redis для долгих проверок (код, видео, песочница).
  Если `USE_CELERY=false` — выполняется через FastAPI BackgroundTasks в том же процессе
- **Песочница**: изоляция через подпроцесс с лимитом времени (и ограничением памяти
  через RLIMIT на Linux) — для алгоритмических решений и запуска тестов команды
- **Инструменты автопроверок**: GitHub API, `git clone` + flake8/radon, PyPDF2,
  python-docx, python-pptx, ffprobe, опционально openai-whisper

### Сервисы (docker compose)

| Сервис | Порт | Описание |
|--------|------|----------|
| `db` | — | PostgreSQL 16 |
| `redis` | — | Брокер и хранилище результатов Celery |
| `backend` | 8000 | FastAPI API (при старте выполняет `seed.py`) |
| `worker` | — | Celery-воркер, обрабатывающий задачи проверок |
| `frontend` | 3000 | React-приложение, раздаётся через Nginx |

### Миграции схемы при запуске

`Base.metadata.create_all` создаёт недостающие таблицы, а лёгкая миграция
(`app/migrate.py`) при старте добавляет новые колонки в уже существующие таблицы.
Благодаря этому имеющаяся база продолжает работать после обновлений без ручных миграций.

## Структура проекта

```
backend/
  app/
    routers/        # эндпоинты: auth, teams, submissions, evaluations,
                    #            leaderboard, algo, cases, criteria,
                    #            checklist, analytics
    checks/         # автопроверки: code, doc, pptx, video, sandbox, runner
    models.py       # модели БД (SQLAlchemy)
    schemas.py      # схемы запросов/ответов (Pydantic)
    config.py       # настройки и переменные окружения
    migrate.py      # авто-добавление колонок при старте
    celery_app.py   # приложение Celery
    queue.py        # выбор очереди: Celery или BackgroundTasks
  seed.py           # демо-данные
frontend/
  src/app/
    pages/          # страницы (дашборды, рейтинг, карточка команды и т.д.)
    components/     # UI-компоненты и общий layout
    context/        # контекст авторизации
    lib/            # API-клиент
```
